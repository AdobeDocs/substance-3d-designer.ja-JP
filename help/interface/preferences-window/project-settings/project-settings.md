# プロジェクト設定

このページでは、[Substance 3D Designer](https://www.adobe.com/jp/products/substance3d-designer.html)の<b>プロジェクトの設定</b>とその中に含まれる設定について説明します。

Substance 3D Designerでは、プロジェクトごとに&#x200B;*環境設定*&#x200B;を作成し、ワークステーション間で共有できます。 これらの環境設定は、[環境設定](../../../interface/preferences-window/preferences-window.md)ウィンドウの<b>プロジェクト</b>タブにあります。

これは、*すべての*&#x200B;システムで&#x200B;*同じ*&#x200B;プロジェクトファイルを使用して、同じプロジェクトで作業するチームに共通の作業環境を設定する場合に非常に便利です。

>[!NOTE]
>
> **生産パイプライン**&#x200B;でのSubstance 3D Designerの設定と統合の詳細については、ドキュメントの[パイプラインおよびプロジェクト構成](../../../pipeline-and-project-con/pipeline-and-project-configuration.md)のセクションを参照して&#x200B;*お勧めします*。

![プロジェクト設定](project-settings.resources/project-settings-01.png "プロジェクト設定"){zoomable="yes"}

## 構成

### 構成ファイル

これにより、Substance 3D Designerの<b>構成ファイル</b>のパスを設定できます。 構成ファイルは<b>\*.sbscfg</b>拡張子を使用し、プロジェクトファイルの一覧と、設定された互換表示設定を含んでいます。

*既定： default\_configuration.sbscfg*

>[!NOTE]
>
> **—config-file**&#x200B;コマンドラインオプションを使用すると、特定の構成ファイルを使用してDesignerを起動できます。\
> 構成ファイルの詳細については、ドキュメントの[構成リスト – SBSCFG](../../../pipeline-and-project-con/configuration-list-sbscfg/configuration-list-sbscfg.md)ページを参照してください。

### プロジェクトファイル

プロジェクトファイルには、Designerの作業環境の重要な要素を定義する様々な設定がタブ形式で記述されています。 これらの設定は、このページのプロジェクトの章にリストされています。 プロジェクトファイルは<b>\*.sbsprj</b>拡張子を使用します。

Designerの作業環境で使用する複数のプロジェクトファイルを読み込むことができます。 複数のプロジェクトファイルが存在する場合、リストである設定（ライブラリ監視パス、エイリアスなど） は&#x200B;*組み合わせ*&#x200B;であり、一意の設定値である設定は、リストの&#x200B;*最後のプロジェクトファイル*&#x200B;によって定義されます。

*既定： default\_project.sbsprj （読み取り専用）, user\_project.sbsprj*

>[!NOTE]
>
> プロダクションパイプラインでプロジェクトファイルを使用する方法の詳細については、ドキュメントの[プロジェクト構成ファイル – SBSPRJ](../../../pipeline-and-project-con/project-configuration-fil/project-configuration-files-sbsprj.md)ページを参照してください。

### 互換性ディスプレイ

最新バージョンのDesignerで作成されたノードの一部は、旧バージョンのSubstance engineと互換性がありません。

<b>互換モード</b>では、選択したノードと互換性のない&#x200B;*非* Substance engineが、黄色のアウトラインで強調表示されます。

*既定： Substance engine v7*

### エイリアス

エイリアスを使用して、システムパスを&#x200B;*短縮*&#x200B;し、チームがアセットをより効率的に&#x200B;*共有*&#x200B;できるようにします。 エイリアスは、*ソフトウェア全体*&#x200B;および&#x200B;*SBSファイル*&#x200B;で使用されます。

これらの設定により、*エイリアスを追加*&#x200B;して&#x200B;*エイリアスを編集*&#x200B;できます。 エイリアスが適用されると、次の構文を使用して、マップされたパスが&#x200B;*置換*&#x200B;されます： <b>://</b>。

例：フォルダー&#x200B;*myFolder*&#x200B;のリソース&#x200B;*myResource*&#x200B;が場所&#x200B;*C:/Users/user/Documents*&#x200B;に配置されている場合、この場所を&#x200B;*myalias*&#x200B;にマッピングすると、リソースが属するSBSパッケージの&#x200B;*myalias://myFolder/myResource*&#x200B;パスがアプリケーション&#x200B;*と*&#x200B;で使用されます。

*既定： sbs; sd-3dview-shapes; sd-3dview-maps; sd-3dview-shaders （既定のプロジェクト）*

>[!WARNING]
>
> エイリアスは&#x200B;*アプリケーションに対してグローバルです*。 これは、アプリケーションで使用される&#x200B;*すべてのパス*&#x200B;と、*読み込まれたSBSPRJプロジェクト設定ファイル*&#x200B;のすべてのパスに適用されることを意味します。 プロジェクト環境を設定する際には、このことを念頭に置いてください。\
> また、*エイリアスをネストしない*&#x200B;ことをお勧めします。つまり、別のエイリアスに含まれているパスにエイリアスを作成します。

### ライブラリ

このセクションでは、[ライブラリ](../../../interface/the-library/the-library.md)の<b>カスタムコンテンツ</b>を管理できます。

<b>追加されたパス</b>の一覧に含まれているすべてのフォルダーのコンテンツがライブラリに追加されます。 コンテンツに加えた変更は、ライブラリに反映されます。これは、[環境設定](../../../interface/preferences-window/preferences-window.md)ウィンドウの[ライブラリ](../../../interface/preferences-window/preferences-window.md) [タブ](../../../interface/preferences-window/preferences-window.md)で設定できる更新期間の後に行います。

リストの列には、これらのフォルダーのコンテンツがライブラリに追加される方法をより詳細に制御できるオプションが表示されます。

* **有効：**&#x200B;フォルダーのコンテンツはライブラリに表示されます（*既定：オン*）
* **再帰的：**&#x200B;すべての子フォルダーのコンテンツもライブラリに表示されます（*既定：オン*）
* **除外パターン:**&#x200B;入力正規表現（正規表現）と一致する&#x200B;*名前*&#x200B;のファイルは&#x200B;*ではなく*&#x200B;で、ライブラリに表示されています（例： `wip-*`） 。 正規表現の構文の詳細については、[こちら](https://doc.qt.io/qt-5/qregularexpression.html#wildcardToRegularExpression)を参照してください。
* **拡張子を除外：**&#x200B;入力テキスト文字列を含む&#x200B;*拡張子*&#x200B;のファイルは、ライブラリに表示されている&#x200B;*ではなく*&#x200B;です。 複数の文字列は`;`個のセミコロンで区切ってください。 (E.g. `jpg;png;tif;fbx`)

SBSパッケージがライブラリに追加される場合、**ライブラリに表示**&#x200B;パラメーターが&#39;はい&#39;に設定されていれば、**グラフ**&#x200B;と&#x200B;**リソース**&#x200B;は個別のエントリとして&#x200B;*ライブラリに表示*&#x200B;されます。\
パッケージ内に新しいグラフまたはリソースを作成または追加するときに、既定で&#x200B;*Yes*&#x200B;に設定する必要があるかどうかを指定できます。

*既定：確認済み*

ライブラリに含まれている[Photoshop](https://www.adobe.com/products/photoshop.html)ドキュメント（\*.PSDファイル）に<b>複数のレイヤー</b>がある場合、ライブラリの*&#x200B;各レイヤーのコンテンツを個別の画像項目*として表示するオプションを使用できます。

*既定：確認済み*

>[!NOTE]
>
> カスタムリソースはライブラリに追加されますが、既存のライブラリカテゴリに対して設定されているフィルタリングルールのため、*表示されない*&#x200B;可能性があります。 プロジェクトの作業中にコンテンツが確実に見つかるように、フォルダーに整理された&#x200B;*独自のフィルター*&#x200B;を作成することをお勧めします。\
> 詳細については、ドキュメントの[カスタムコンテンツとフィルターの管理](../../the-library/managing-custom-content/managing-custom-content-and-filters.md)セクションを参照してください。

### バージョン管理

>[!WARNING]
>
> [Perforce](https://www.perforce.com/)は、現在バージョン管理でサポートされている&#x200B;*のみ*&#x200B;ツールです。

[バージョン管理](../../../interface/preferences-window/version-control/version-control.md)ページを参照してください。

**これを使用する方法を選択してください。**

Designerのプロジェクトファイル(\*.sbsprj)には、*&#x200B;プロジェクト固有*のすべての環境設定を指定する必要があります。 これらの環境設定には、次のものが含まれます。

* 接線空間プラグイン
* ライブラリ
* エイリアス
* 3D表示設定
* ベイク処理の設定
* [バージョン管理の設定](../../../interface/preferences-window/version-control/version-control.md)

すべてのパスは、プロジェクトファイル(.spsprj)の&#x200B;*相対パス*&#x200B;として保存されます。 perforceのプロジェクトファイルと同じ場所に&#x200B;**library**&#x200B;フォルダーを作成し、次のサブフォルダーツリーを作成します。

* マップ/
* メッシュ/
* sbs/
* sbsar/
* psd/
* 3Dビュー/
* ...

プロジェクトファイルと同じレベルに、接線空間プラグインまたはデフォルトのシェーダを保存することもできます。

設定ファイル(\*.sbscfg)は、プロジェクトファイルと共にPerforceワークスペースに配置する必要があります。

>[!NOTE]
>
> **生産パイプライン**&#x200B;でのSubstance 3D Designerの設定と統合の詳細については、ドキュメントの[パイプラインおよびプロジェクト構成](../../../pipeline-and-project-con/pipeline-and-project-configuration.md)のセクションを参照して&#x200B;*お勧めします*。
