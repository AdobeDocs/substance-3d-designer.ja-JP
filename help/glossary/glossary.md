# Designerの用語や概念について説明します。

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene" data-preserve-html="true"></span>3Dシーン</b> | 3D空間のビジュアライゼーションを表現およびアニメートするために必要なオブジェクトとデータのコレクション。<ul data-preserve-html="true"> <li data-preserve-html="true">[メッシュ](#mesh)</li> <li data-preserve-html="true">[マテリアル](#material)</li> <li data-preserve-html="true">カメラ</li> <li data-preserve-html="true">ライト</li> <li data-preserve-html="true">アニメーション</li> <li data-preserve-html="true">シミュレーション</li> <li data-preserve-html="true">...</li> </ul>3Dシーンを保存する[一般的なファイル形式](https://www.adobe.com/jp/products/substance3d/discover/3d-files-formats.html)には、Pixarの[USD](#usd)やAutodeskのFBXが含まれます。 すべてのファイル形式が、これらのコンポーネントをすべてサポートしているわけではありません |

## A

| <b><span id="alpha" data-preserve-html="true"></span>Alphaチャンネル</b> | カラー画像の4番目のチャンネル。不透明度を表すのに使用されます。 |
| <b><span id="ambient-occlusion" data-preserve-html="true"></span>環境オクルージョン</b> | 露光量が少なく、そのため到達が困難なサーフェス上の環境光の減衰。 |
| <b><span id="anisotropy" data-preserve-html="true"></span>異方性</b> | 方向に依存するプロパティ。 つまり、異なる軸で測定または観察された場合に異なる結果を提供します。<br><br>異方性マテリアルは、見た場所によって外観が異なり、異方性フィルタがすべての方向に均一に適用されることはありません。 |
| <b><span id="aov" data-preserve-html="true"></span>AOV</b> | 任意出力変数(AOV)とは、[レンダリング](#rendering)で使用される用語で、深度、法線、カスタムデータなど、レンダリングから出力できる追加のデータチャンネルを表します。 |
| <b><span id="api" data-preserve-html="true"></span>API</b> | アプリケーションプログラミングインターフェイス(API)は、ユーザーがプログラムの別のアプリケーションの関数およびプロシージャにアクセスできるようにする関数およびプロシージャの集まりです。<br><br>APIは、ユーザーとプログラムの間に、制御された安全な層を提供します。 また、他のプログラミング言語を使用して、プログラムの操作を容易にし、より広くアクセスできるようにします。<br><br>Designerは[Python API](../scripting/scripting.md)を提供しており、データの操作、カスタムツールの作成、ワークフローの高速化を行うための幅広い機能に簡単にアクセスできます。 |
| <b><span id="atomic-node" data-preserve-html="true"></span>アトミックノード</b> | グラフの基本的な構成単位。 すべての[インスタンス化](#instance-node)は、アトミックノードのグラフに分割できます。<br>各グラフの種類には、独自のアトミックノードのセットがあります。 |

## B

|                                                                                          |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
|------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="baking" data-preserve-html="true"></span>ベイク処理</b> | 3Dモデルから情報を計算し、その結果を[テクスチャ](#texture)に保存するプロセス。 データは、モデルの[UV](#uv)に従ってテクスチャに配置されます。 |
| <b><span id="base-color" data-preserve-html="true"></span>基本色</b> (アルベド) | PBRメタリックの粗さ[シェーディング](#shader)モデルを使用して定義された[マテリアル](#material)のチャンネル。<br>Base colorは、照明を含まないサーフェスの色を指定します。<br><br>[Diffuse](#diffuse)と混同しないでください。 |
| <b><span id="base-parameter" data-preserve-html="true"></span>基本パラメーター</b> | [ビットマップ](#bitmap)を計算するSubstanceグラフ内のすべてのノードに共通のパラメーター。<br><br>これらには、解像度（[出力サイズ](#output-size)）および[ビット深度](#bit-depth) （[出力フォーマット](#output-format)）、またはビットマップの計算方法（[タイリング](#tiling)モードなど）のような、ビットマップの主要な要素が含まれます。<br><br>基本パラメーターは、通常、上流の他のノードまたはノードをホストしているグラフーから[継承](#inheritance)されています。 |
| <b><span id="bilinear-filtering" data-preserve-html="true"></span>バイリニアフィルター</b> | [テクスチャサンプル](#texture-sampling)がピクセルの中心で正確に実行されていない場合に、コンピュータのイメージングで使用される補間処理。<br><br>たとえば、画像が拡大された場合に発生する可能性があります。 |
| <b><span id="bit-depth" data-preserve-html="true"></span>ビット深度</b> | テクスチャ内のピクセルの値を格納するために使用されるビット数。 ビット深度が高いほど、より多くの値をエンコードでき、グラデーションが滑らかになります。<br><br>値の種類に応じて、さまざまなビット深度を使用できます： – 整数値は8ビット(0 ～ 255)または16ビット(0 ～ 65,535)を使用してエンコードできます。  – 浮動小数点値は16ビット(+32767.9999 ～ -32768.0)または32ビット(-3.4E+38 ～ +3.4E+38)を使用してエンコードできます<br><br>低ダイナミックレンジ画像では、0 ～ 1のステップをエンコードするために整数値を使用します。 ハイダイナミックレンジ画像では、浮動小数点を使用して生の数値をエンコードします。<br><br>Substanceグラフでは、ビット深度は[Output Format](#output-format)パラメーターで制御されます。 |
| <b><span id="bitmap" data-preserve-html="true"></span>ビットマップ</b> | デジタル画像。 次の2種類の画像が最も一般的です。<ul data-preserve-html="true"> <li data-preserve-html="true">グレースケール画像には、輝度(L)チャンネルが1つだけ含まれます。</li> <li data-preserve-html="true">カラー画像には、赤、緑、青(RGB)の3つのチャンネルがあります。 4つ目の1つは次のとおりです： [アルファ](#alpha) (A)。これは不透明度によく使用されます。 Designerのカラー画像は常にRGBAです。</li> </ul>  ビットマップは、値のグリッドと考えることができます。 そのグリッドの各セルはピクセルであり、「画像要素」の略です。 ピクセルには、チャンネルごとに1つの値が格納されます。 この値の種類は、ビットマップの[ビット深度](#bit-depth)によって異なります。 |

## C

|                                                                                                                                          |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
|------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="cache" data-preserve-html="true"></span>キャッシュ</b> （メモリ） | データの収集 – 例： ノードの[基本パラメーター](#base-parameter)と出力イメージ – 再利用するためにメモリに格納されます。<br><br>キャッシュを使用すると、[Substance engine](#substance-engine)で変更されたグラフの部分のみを再計算できるため、グラフの計算が大幅に高速化されます。 ノードの接続とパラメーターを調整する場合、そのノードより前のすべてのノードがそれらの変更の影響を受けないので、グラフを更新するために再度[評価](#evaluation)する必要はありません。 代わりにキャッシュが使用されます。<br><br>大きなグラフで高解像度およびビット深度を使用する場合、キャッシュのメモリフットプリントが大きくなる可能性があります。 |
| <b><span id="channel-packing" data-preserve-html="true"></span>チャンネルパッキング</b> | 単色画像のRGB(A)チャンネルに個別の画像をパックする最適化手法。<br><br>たとえば、RMA テクスチャは、[ラフネス](#roughness)マップ(R)、メタネスマップ(M)、および[ambient occlusion](#ambient-occlusion)マップ(A)がすべて1つのカラーテクスチャにパックされています。<br><br>もう1つの一般的な手法は、グレースケールテクスチャを[法線マップ](#normal-map)の青チャンネルにパッキングすることです。青チャンネル（法線ベクトルの&#39;Up&#39;コンポーネント）は実行時に再計算できるためです。<br><br>[RGBAマージ](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md)ノードは、この手法を実装する場合に便利です。 |
| <b><span id="color-space" data-preserve-html="true"></span>カラースペース</b> | カラーの範囲の表示方法の定義。<br>特定の色をデジタルでエンコードおよびデコードするには、使用する数値を理解するためのこのような定義が必要です。<br><br>イメージファイルには、指定されたカラースペースを使用してカラー値が保存されます。そのため、そのカラースペースをサポートするディスプレイで、これらのカラーを忠実に再現することができます。 ディスプレイは特定の色再現機能を持ち、特定の色空間を完全に、または部分的にサポートすることができます。<br><br>未加工データ – 例： [法線マップ](#normal-map) – は、リニアカラースペースで常にエンコードおよびデコードされます。これらのカラーは、表示したり、変換したりするためのものではないためです。<br><br>sRGBは、広くサポートされているカラースペースです。 その他の人気のあるカラースペースには、Adobe RGB、Recがあります。 2100およびProPhoto RGB。 |
| <b><span id="cooking" data-preserve-html="true"></span>料理</b> （<span id="compilation" data-preserve-html="true"></span>コンパイル） | データを別の言語に翻訳して、すばやく効率的に実行できるようにするプロセス。<br>グラフの結果を計算するには、まずコンパイルする必要があります。 コンパイルはグラフ [評価](#evaluation)プロセスの一部です。<br><br>このコンパイルは、フラット化されたグラフに対して実行されます。つまり、すべての[インスタンス化](#instance-node)が元のグラフに「置き換えられ」、より大きなグラフが1つ残り、そのグラフがコンパイルされます。<br><br>コンパイルされたグラフは編集できません。 公開されたパラメーターは、[動的](#dynamic-parameter)である場合は使用可能ですが、[静的](#static-parameter)パラメーターはロックされ、非表示になっています。 |
| <b><span id="culling"></span>カリング</b> | [レンダリング](#rendering) [3D シーン](#three-d-scene)の最適化手法。レンダリングの計算が表示されていないときにジオメトリを削除します。<br><br>これには、カメラの基数（*基数カリング*）の外側にあるオブジェクトまたはポリゴンが含まれる場合があり、カメラ(*バックフェースカリング*)から対角線上に面しているか、他の不透明なオブジェクトに完全に隠されている場合（*オクルージョンカリング*）があります。 |

## D

|                                                                                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|----------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="dependency" data-preserve-html="true"></span>依存関係</b> | ファイルAが存在しない場合にファイルBが意図したとおりに機能しないファイルAです。<br><br>[パッケージ](#package)の依存性は、パッケージ内のグラフ、イメージファイル、フォントなどを参照するため、別のパッケージになる可能性があります。<br><br>パッケージには依存性へのパスが含まれており、そのパスで依存性が見つからない場合、警告が表示されます。 依存関係が見つからない場合も、グラフで[ゴーストインスタンスノード](#ghost-instance-node)が発生する可能性があります。 |
| <b><span id="diffuse" data-preserve-html="true"></span>拡散</b> | PBR Specular光沢[シェーディング](#shader)モデルを使用して定義された[マテリアル](#material)のチャンネル。 [拡散反射光]ライトを付けたときのサーフェスのカラーを指定します。<br><br>[Base color(アルベド)](#base-color)と混同しないでください。 |
| <b><span id="directx" data-preserve-html="true"></span>DirectX</b> | マルチメディアコンテンツを処理するためのAPIのコレクション。 その3D APIであるDirect3Dは、ビデオゲームの開発やその他の3D業界で広く使用されています。<br><br>Direct3Dはテクスチャの原点、つまり、(0, 0)座標を&#x200B;*左上*&#x200B;に配置し、（Y – ダウン）、[OpenGL](#opengl) APIは&#x200B;*左下* （Y – アップ）に配置します。<br><br>DirectX [法線マップ](#normal-map)は、OpenGLと比較して&#x200B;*逆チャンネルを有しますつまり、*&#x200B;実際、緑チャンネルは法線ベクトルのY座標をホストしています。 |
| <b><span id="displacement" data-preserve-html="true"></span>ディスプレイスメント</b> | 3Dモデルの[頂点](#vertex)を、多くの場合、[法線](#normal)に沿って移動させるプロセス。<br><br>ディスプレイスメントは、多くの場合、[テセレーション](#tessellation)および[法線マップ](#normal-map)と組み合わせて使用され、表面の細部を細かくモデル化します。 |
| <b><span id="dynamic-parameter" data-preserve-html="true"></span>動的パラメーター</b> | 値が変更される可能性のあるパラメータ。 つまり、値が一定でないパラメータは動的です。<br><br><br>これには、表示されるパラメーター、表示されるパラメーターの影響を受けるパラメーター、および[テクスチャでのサンプリング](#texture-sampling)の影響を受けるパラメーター値が含まれます。<br><br>[静的パラメーター](#static-parameter)とは対照的に、動的パラメーターの値は、グラフーが[Sbsar ファイル](#sbsar-file)にコンパイルされた後に、その場で調整できます。 |

## E

|                                                                          |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|--------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="evaluation" data-preserve-html="true"></span>評価版</b> | グラフ内のデータおよびパラメータの伝播を解決するプロセス。 評価では、グラフとその接続の有効性を検証し、グラフを[継承](#inheritance)および[フック](#cooking)します。<br><br>グラフビューでは、接続が評価されない場合、接続は点線で表されます。<br>評価により、接続が実線に変換されます。<br><br><br>グラフでパラメーターを調整するたびに、このパラメーターをホストしているノードとダウンストリームのすべてのノードが[無効](#invalidation)になり、[レンダリング](#rendering)される前に再評価する必要があります。 |

## G

|                                                                                            |                                                                                                                                                                                                                                                                                                                                                                                        |
|--------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="ghost-instance-node" data-preserve-html="true"></span>ゴーストインスタンスノード</b> | 見つからない[インスタンス化](#subgraph)を参照している[サブグラフ](#instance-node)が、ゴーストインスタンス化として読み込まれています（つまり、[依存関係](#dependency)が見つかりません）。<br><br>ゴーストインスタンスノードは、見つからない依存関係を解決し、[パッケージ](#package)を再度読み込むことによって、予期された状態に復元されます。 |
| <b><span id="glossiness" data-preserve-html="true"></span>光沢</b> | PBR Specular光沢[シェーディング](#shader)モデルを使用して定義された[マテリアル](#material)のチャンネル。 光沢は表面の粗さを表します。つまり、Heightの微細なバリエーションで、*マイクロファセット*&#x200B;とも呼ばれます。<br><br>光沢を高くすると滑らかな外観になりますが、光沢を低くすると粗くマットな外観になります。<br><br>[粗さ](#roughness)の逆です。 |

## H

|                                                                                |                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|--------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="histogram" data-preserve-html="true"></span>ヒストグラム（画像）</b> | 画像では、ヒストグラムは与えられた範囲（通常[0, 1]）の値の母集団を表します。<br><br>この母集団は縦の棒で視覚化されます。この棒は、画像内に存在する値ほど、その値に対して高い棒になります。<br>棒グラフは、低い値（暗）から高い値（明）まで水平方向に分布します。<br><br>通常、カラー画像のヒストグラムは、各チャンネル（通常はR、G、B）のヒストグラムと重なります。 |

## I

|                                                                                |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
|--------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="inheritance" data-preserve-html="true"></span>継承</b> | Substanceグラフのコンテキストでは、上位ノードまたは親グラフからパラメータ値を取得するノードのプロパティを表します。<br><br>継承されたパラメーターには、[解像度](#resolution) （[出力サイズ](#output-size)）、[ビット深度](#bit-depth) （[出力形式](#output-format)）および[分割](#tiling)モードが含まれます。<br><br>継承の詳細については、この[専用ページ](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md)をご覧ください。 |
| <b><span id="instance-node" data-preserve-html="true"></span>インスタンスノード</b> | インスタンスノードはグラフAを別のグラフBに表す。その場合、グラフAはグラフBの[サブグラフ](#subgraph)と呼ばれることがあります。グラフAの変更は、グラフAを表すすべてのインスタンスノードに反映されます。<br><br>インスタンスノードは、グラフBのコンテキストでグラフAの入力パラメーターに対して独自の値のセットを適用します。その意味で、グラフBは、グラフAを参照するが、グラフAへの入力として異なる値またはテクスチャをそれぞれ渡す複数のインスタンスノードをホストできる。<br><br>Designerライブラリ内の、[アトミックノード](#atomic-node)以外のすべてのノードは、インスタンスノードである。 |
| <b><span id="invalidation" data-preserve-html="true"></span>無効化</b> | ノードの結果が古いことを宣言するプロセス。<br><br>パラメーターを調整すると、このパラメーターをホストするノードとダウンストリームのすべてのノードが無効になるため、[評価](#evaluation)して[レンダリング](#rendering)する必要があります。 |

## M

|                                                                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|----------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="material" data-preserve-html="true"></span>マテリアル</b> | サーフェスと土量を含む、空間内の物質のプロパティと動作のコレクション。<br>3D空間での図形の外観は、そのマテリアルによって定義されます。<br><br>マテリアルは様々な方法で定義される可能性があります。すべての定義は、屈折、異方性、光沢などすべてのプロパティをサポートしているわけではありません。 [シェーダ](#shader)は、マテリアル定義の特定の実装です。<br><br><b>重要：</b> 「マテリアル」という用語は、*傘*&#x200B;の用語で、次のものを指すために使用されます。<ul data-preserve-html="true"> <li data-preserve-html="true">サーフェスまたはボリュームの外観の計算に使用される[シェーダ](#shader)。</li> <li data-preserve-html="true">シェーダに提供された[テクスチャ](#texture)のセット；</li> <li data-preserve-html="true">マテリアルID。3Dプリミティブのアトリビュートで、異なるマテリアルを使用するパーツを区別するために使用されます。</li> </ul> |
| <b><span id="mesh" data-preserve-html="true"></span>メッシュ</b> | 三角形などの多角形を形成するためにエッジで接続された[頂点](#vertex)で構成される3Dオブジェクト。多角形は次にサーフェスに組み立てられます。 これらのサーフェスは、開いていても閉じていても構いません。<br><br>これらのサーフェスの外観は、割り当てられた[マテリアル](#material)によって定義されます。<br>メッシュの詳細レベルは、[ポリカウント](#polycount)にも大きく依存しています。 |

| <b><span id="tessellation" data-preserve-html="true"></span>テセレーション</b> | コンピューターグラフィックスでは、テセレーションはサーフェスをより多くのポリゴン（多くの場合は三角形）にサブディバイドするプロセスです。<br><br>このプロセスは、3Dモデルのポリゴンの量を動的に増やすために実行時に実行できます。多くの場合、[ディスプレイスメント](#displacement)および[法線マップ](#normal-map)と組み合わせて、追加されたポリゴンを使用してより細かいモデルを作成します。 |
| <b><span id="texel" data-preserve-html="true"></span>テキスト</b> | ピクセルが画像の情報単位である場合と同様に、[テクスチャ](#texture)の情報単位。 |
| <b><span id="texture" data-preserve-html="true"></span>テクスチャ</b> | グラフィックスを表したり、[データ](#shader)に値を指定してサーフェスの[マテリアル](#material)のプロパティを表したり、その[シェーダー](#texel)で生データをエンコードしたりするために使用されるイメージです。<br><br>テクスチャは、GPUによって非常に効率的に圧縮解除および操作できるオブジェクトです。 多くの場合、この効率性を実現するには、テクスチャが2つの解像度（1024 x 1024、4096 x 4096、512 x 256など）の電力を利用する必要があります。 |
| <b><span id="texture-sampling" data-preserve-html="true"></span>テクスチャサンプリング</b> | 特定の場所にある[テクスチャ](#texture)の値を取得しています。<br><br>アルゴリズムによっては、値の比較、平均値の算出、その他の操作のために、多くのサンプルを実行する必要があります。<br><br>ピクセルの中心で正確にサンプルを行わない場合、Designerには、取得する必要がある値に対する次の2つのオプションがあります。<ul data-preserve-html="true"> <li data-preserve-html="true"><b>最も近いピクセル：</b>中心に基づく最も近いピクセルの値</li> <li data-preserve-html="true"><b>[フィルタリング](#bilinear-filtering):</b>隣り合うピクセル間の縦と横の補間値。近いピクセルほど重みが大きくなります。</li> </ul> |
| <b><span id="tiling" data-preserve-html="true"></span>タイリング</b> | 視覚的なシームまたは視覚的な不連続性を伴わない、水平方向、垂直方向、またはその両方のイメージの繰り返し。<br><br>Designerは、そのタイルを[ノイズ](#noise)または[パターン](#pattern)生成する[ノード](#node)を多数提供しています。 同様に、多くの[filter](#filter)ノードは、タイリングを維持しながら画像を処理するように設計されています。 |

## U

|                                                                         |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
|-------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <b><span id="usage" data-preserve-html="true"></span>使用方法（出力）</b> | グラフでは、Usageは、[3Dビュー](../interface/3d-view/3d-view.md)で[テクスチャ](#texture)を[シェーダー](#shader)に接続する方法をアプリケーションに知らせるために使用される[Output](../compositing-graphs/nodes-reference-for-com/atomic-nodes/output/output.md)ノードの属性です。<br><br>3Dビューにグラフを適用すると、すべての出力が一致する使用状況に基づいてシェーダーに接続されます。 つまり、「basecolor」を「basecolor」に、「ラフネス」を「ラフネス」に変換するなどです。<br><br>&#39;マテリアル&#39;および&#39;コンパクトマテリアル&#39; [リンク作成モード](../interface/the-graph-view/link-creation-modes/link-creation-modes.md)を使用する場合、コネクターの一致にも使用されます。 |
| <b><span id="udim" data-preserve-html="true"></span>UDIM</b> （UVタイル） | [UV](#uv)スペースを一意の数値識別子のタイルに分割するための標準。これにより、各タイルに異なる[テクスチャ](#texture)を割り当てることができます。<br><br>UDIMワークフローはVFXパイプラインでは一般的であり、忠実度の高いアセットには非常に詳細な情報が必要なため、複数の高解像度のテクスチャが必要です。 その場合、アセットの[UV](#uv)は複数のUDIM （またはUVタイル）に配置されています。<br><br>DesignerはUDIMワークフローをサポートしており、UDIMごとに異なるSubstanceグラフを割り当てることができます。 |
| <b><span id="usd" data-preserve-html="true"></span>USD</b> （またはOpenUSD） | [Universal Scene Description](https://openusd.org/release/index.html) (USD)は、Pixarによって構築された、アプリケーションやプラットフォーム間での相互運用と3D シーン交換を目的としたデータ記述形式です。<br><br>USDファイルには、シーンで使用されるデータの定義と、そのシーンの構成が含まれ、モデル、マテリアル、カメラ、アニメーション、シミュレーションなどが含まれます。<br><br>USDファイルには、データを正しく読み取って使用できるUSDプラグインにアクセスできる場合、あらゆる種類のデータが含まれます。<br><br>Adobeは、[Alliance for OpenUSD](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd)に参加しています。これは、3D業界のアクターが集まり、フォーマットの開発と標準化に積極的に取り組んでいる団体です。 |
| <b><span id="uv" data-preserve-html="true"></span>UV</b> | UV は、2D スペース内で 3D モデルを表現したものです。 2D 画像を 2D スペースから 3D スペースのモデルのサーフェスにマッピングするために使用されます。<br><br>UVを作成するプロセスは、多くの場合、シームをモデルにカットして展開および平坦化します。 |
