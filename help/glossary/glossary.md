# Designerの用語や概念について説明します。

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene"></span>3Dシーン</b> | 3D空間のビジュアライゼーションを表現およびアニメートするために必要なオブジェクトとデータのコレクション。<ul data-preserve-html="true"> <li data-preserve-html="true">[メッシュ](#mesh)</li> <li data-preserve-html="true">[マテリアル](#material)</li> <li data-preserve-html="true">カメラ</li> <li data-preserve-html="true">ライト</li> <li data-preserve-html="true">アニメーション</li> <li data-preserve-html="true">シミュレーション</li> <li data-preserve-html="true">...</li> </ul>3Dシーンを保存する[一般的なファイル形式](https://www.adobe.com/products/substance3d/discover/3d-files-formats.html)には、Pixarの[USD](#usd)やAutodeskのFBXが含まれます。 すべてのファイル形式が、これらのコンポーネントをすべてサポートしているわけではありません |

## A

|  |  |
| --- | --- |
| <b><span id="alpha"></span>Alphaチャンネル</b> | カラー画像の4番目のチャンネル。不透明度を表すのに使用されます。 |
| <b><span id="ambient-occlusion"></span>環境オクルージョン</b> | 露光量が少なく、そのため到達が困難なサーフェス上の環境光の減衰。 |
| <b><span id="anisotropy"></span>異方性</b> | 方向に依存するプロパティ。 つまり、異なる軸で測定または観察された場合に異なる結果を提供します。   異方性マテリアルの外観は見た場所によって異なり、異方性フィルタはすべての方向に均一に適用されるわけではありません。 |
| <b><span id="aov" ></span>AOV</b> | 任意出力変数(AOV)とは、[レンダリング](#rendering)で使用される用語で、深度、法線、カスタムデータなど、レンダリングから出力できる追加のデータチャンネルを表します。 |
| <b><span id="api"></span>API</b> | アプリケーションプログラミングインターフェイス(API)は、ユーザーがプログラムの別のアプリケーションの関数およびプロシージャにアクセスできるようにする関数およびプロシージャの集まりです。   APIは、ユーザーとプログラムの間に、制御された安全なレイヤーを提供します。 また、他のプログラミング言語を使用して、プログラムの操作を容易にし、より広くアクセスできるようにします。   Designerは[Python API](../scripting/scripting.md)を提供しており、データの操作、カスタムツールの作成、ワークフローの高速化を行うための広範な機能に簡単にアクセスできます。 |
| <b><span id="atomic-node"></span>アトミックノード</b> | グラフの基本的な構成単位。 すべての[インスタンスノード](#instance-node)は、アトミックノードのグラフに分割できます。 各グラフの種類には、固有のアトミックノードのセットがあります。 |

## B

|  |  |
| --- | --- |
| <b><span id="baking"></span>ベイク処理</b> | 3Dモデルから情報を計算し、その結果を[テクスチャ](#texture)に保存するプロセス。 データは、モデルの[UV](#uv)に従ってテクスチャに配置されます。 |
| <b><span id="base-color"></span>基本色</b> (アルベド) | PBRメタリックの粗さ[シェーディング](#shader)モデルを使用して定義された[マテリアル](#material)のチャンネル。 基本色：照明情報を含まないサーフェスの色を指定します。   [拡散](#diffuse)と混同しないでください。 |
| <b><span id="base-parameter"></span>基本パラメーター</b> | [ビットマップ](#bitmap)を計算するSubstanceグラフ内のすべてのノードに共通のパラメーター。   これらには、解像度（[出力サイズ](#output-size)）および[ビット深度](#bit-depth) （出力フォーマット）、またはビットマップの計算方法（[タイリング](#tiling)モードなど）など、ビットマップのコアとなる側面が含まれます。   基本パラメーターは、多くの場合、上流の他のノードまたはノードをホストしているグラフから[継承](#inheritance)されています。 |
| <b><span id="bilinear-filtering"></span>バイリニアフィルター</b> | [テクスチャサンプル](#texture-sampling)がピクセルの中心で正確に実行されていない場合に、コンピュータのイメージングで使用される補間処理。   例えば、画像が拡大された場合に発生する可能性があります。 |
| <b><span id="bit-depth"></span>ビット深度</b> | テクスチャ内のピクセルの値を格納するために使用されるビット数。 ビット深度が高いほど、より多くの値をエンコードでき、グラデーションが滑らかになります。   値の種類に応じて、さまざまなビット深度を使用できます。 – 整数値は8ビット(0 ～ 255)または16ビット(0 ～ 65,535)を使用してエンコードできます。  – 浮動小数点値は16ビット（+32767.9999から – 32768.0）または32ビット（–3.4E+38から+3.4E+38）を使用してエンコードできます。低ダイナミックレンジ画像では、0 ～ 1のステップをエンコードするために整数値を使用します。 ハイダイナミックレンジ画像では、浮動小数点を使用して生の数値をエンコードします。   Substanceグラフのビット深度は、「出力フォーマット」パラメーターで制御します。 |
| <b><span id="bitmap"></span>ビットマップ</b> | デジタル画像。 次の2種類の画像が最も一般的です。<ul data-preserve-html="true"> <li data-preserve-html="true">グレースケール画像には、輝度(L)チャンネルが1つだけ含まれます。</li> <li data-preserve-html="true">カラー画像には、赤、緑、青(RGB)の3つのチャンネルがあります。 4つ目の1つは、不透明度にしばしば使用されるα(A)である。 Designerのカラー画像は常にRGBAです。</li> </ul>  ビットマップは、値のグリッドと考えることができます。 そのグリッドの各セルはピクセルであり、「画像要素」の略です。 ピクセルには、チャンネルごとに1つの値が格納されます。 この値の種類は、ビットマップの[ビット深度](#bit-depth)によって異なります。 |

## C

|  |  |
| --- | --- |
| <b><span id="cache"></span>キャッシュ</b> （メモリ） | データの収集 – 例： ノードの[基本パラメーター](#base-parameter)と出力イメージ – 再利用するためにメモリに格納されます。   キャッシュを使用すると、[Substance engine](#substance-engine)はグラフの変更された部分のみを再計算できるため、グラフの計算が大幅に高速化されます。 ノードの接続とパラメーターを調整する場合、そのノードより前のすべてのノードがそれらの変更の影響を受けないので、グラフを更新するために再度[評価](#evaluation)する必要はありません。 代わりにキャッシュが使用されます。   大きなグラフで高解像度やビット深度を使用する場合、キャッシュのメモリ使用量が大幅に増加することがあります。 |
| <b><span id="channel-packing"></span>チャンネルパッキング</b> | 単色画像のRGB(A)チャンネルに個別の画像をパックする最適化手法。   たとえば、RMAテクスチャは、粗さマップ(R)、メタネスマップ(M)、周囲光オクルージョンマップ(A)が、すべて1つのカラーテクスチャにパックされています。   もう1つの一般的なテクニックは、グレースケールテクスチャを法線マップの青チャンネルにパッキングすることです。これは、青チャンネル（法線ベクトルの「上」コンポーネント）が実行時に再計算できるためです。   [RGBAマージ](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md)ノードは、この手法を実装する場合に便利です。 |
| <b><span id="color-space"></span>カラースペース</b> | カラーの範囲の表示方法の定義。 特定のカラーをデジタルエンコーディングおよびデコードするには、使用する数値を意味するこのような定義が必要です。   画像ファイルは、指定されたカラースペースを使用してカラー値を保存するので、そのカラースペースをサポートするディスプレイでこれらのカラーを忠実に再現することができます。 ディスプレイは特定の色再現機能を持ち、特定の色空間を完全に、または部分的にサポートすることができます。   未加工データ – 例： 法線マップは、常にリニアカラースペースでエンコードおよびデコードされます。これらのカラーは表示するためのものではなく、データに変換を適用する必要がないためです。   sRGBは広くサポートされているカラースペースです。 その他の人気のあるカラースペースには、Adobe RGB、Recがあります。 2100およびProPhoto RGB。 |
| <b><span id="cooking"></span>調理中</b>（<span id="compilation"></span>コンパイル） | データを別の言語に翻訳して、すばやく効率的に実行できるようにするプロセス。 Substanceグラフの結果を計算するには、まず計算グラフをコンパイルする必要があります。 コンパイルはグラフ[評価](#evaluation)プロセスの一部です。   このコンパイルは、平坦化されたグラフに対して実行されます。つまり、すべての[インスタンスノード](#instance-node)が元のグラフに「置き換えられ」、1つの大きなグラフが残り、そのグラフがコンパイルされます。   コンパイルされたグラフは編集できません。 公開されたパラメーターは、[動的](#dynamic-parameter)である場合は使用可能ですが、[静的](#static-parameter)パラメーターはロックされ、非表示になっています。 |
| <b><span id="culling"></span>カリング</b> | 3Dシーンをレンダリングするための最適化テクニック。レンダリングが表示されていない場合に、レンダリングの計算からジオメトリを削除します。   これには、カメラの構図（*構図カリング*）の外側にあるオブジェクトまたはポリゴン、カメラから反対側に面しているオブジェクト（*背面カリング*）、または他の不透明なオブジェクトに完全に隠されているオブジェクトまたはポリゴン（*オクルージョンカリング*）が含まれる場合があります。 |

## D

|  |  |
| --- | --- |
| <b><span id="dependency"></span>依存関係</b> | ファイルAが存在しない場合にファイルBが意図したとおりに動作しない方法で他のファイルBによって使用されるファイルA。   [パッケージ](#package)の依存関係は、内部のグラフ、イメージファイル、フォントなどを参照するため、別のパッケージになる可能性があります。パッケージには依存関係へのパスが格納され、そのパスで依存関係が見つからない場合は警告が発生します。 依存関係が見つからない場合も、グラフで[ゴーストインスタンスノード](#ghost-instance-node)が発生する可能性があります。 |
| <b><span id="diffuse"></span>拡散</b> | PBR Specular光沢[シェーディング](#shader)モデルを使用して定義された[マテリアル](../glossary/glossary.md)のチャンネル。 [拡散反射光]ライトを付けたときのサーフェスのカラーを指定します。   [基本色(アルベド)](#base-color)と混同しないでください。 |
| <b><span id="directx"></span>DirectX</b> | マルチメディアコンテンツを処理するためのAPIのコレクション。 3D APIであるDirect3Dは、ビデオゲーム開発や他の3D業界で広く使用されています。   Direct3Dは、テクスチャの原点、つまり、(0, 0)座標を&#x200B;*左上*&#x200B;に配置します(Y-down)。一方、[OpenGL](#opengl) APIは&#x200B;*左下*&#x200B;に配置します(Y-up)。   これは、DirectX法線マップに、OpenGLと比較して&#x200B;*反転した緑チャンネル*&#x200B;があることを意味します。 実際、緑チャンネルは法線ベクトルのY座標をホストしています。 |
| <b><span id="displacement"></span>ディスプレイスメント</b> | 3Dモデルの[頂点](#vertex)を、多くの場合、[法線](#normal)に沿って移動させるプロセス。   ディスプレイスメントは、多くの場合、[テッセレーション](#tessellation)と[法線マップ](#normal-map)と組み合わせて使用され、サーフェス上でより細かいディテールをモデリングします。 |
| <b><span id="dynamic-parameter"></span>動的パラメーター</b> | 値が変更される可能性のあるパラメータ。 つまり、値が一定でないパラメータは動的です。    これには、公開されたパラメーター、公開されたパラメーターの影響を受けるパラメーター、および[テクスチャでのサンプリング](#texture-sampling)の影響を受けるパラメーター値が含まれます。   [静的パラメーター](#static-parameter)とは対照的に、動的パラメーターの値は、グラフがSBSARファイルにコンパイルされた後に、その場で調整できます。 |

## E

|  |  |
| --- | --- |
| <b><span id="evaluation"></span>評価版</b> | グラフ内のデータおよびパラメータの伝播を解決するプロセス。 評価は、グラフとその接続の有効性を確認し、グラフに[継承](#inheritance)を適用し、[調理](#cooking)を行います。   グラフビューでは、評価されない場合、接続は点線で表示されます。 評価により、接続が実線に変換されます。    グラフでパラメーターを調整するたびに、このパラメーターをホストしているノードとダウンストリームのすべてのノードが[無効](#invalidation)になり、[レンダリング](#rendering)される前に再評価する必要があります。 |

## F

|  |  |
| --- | --- |
| <b><span id="filter"></span>フィルター</b> （ノード） | イメージに変更（例えば、変形）を適用したり、そこから情報（例えば、マスク）を抽出したりするノード。 |

## G

|  |  |
| --- | --- |
| <b><span id="ghost-instance-node"></span>ゴーストインスタンスノード</b> | 見つからないサブグラフを参照している[インスタンスノード](#instance-node)が、ゴーストインスタンスノードとして読み込まれています（つまり、[依存関係](#dependency)が見つかりません）。   ゴーストインスタンスノードは、見つからない依存関係を解決し、[パッケージ](#package)を再読み込みすることで、予期された状態に復元されます。 |
| <b><span id="glossiness"></span>光沢</b> | PBR Specular光沢[シェーディング](../glossary/glossary.md)モデルを使用して定義された[マテリアル](../glossary/glossary.md)のチャンネル。 光沢は表面の粗さを表します。つまり、Heightの微細なバリエーションで、*マイクロファセット*&#x200B;とも呼ばれます。   光沢を高くすると滑らかな外観になりますが、光沢を低くすると粗くマットな外観になります。   [粗さ](#roughness)の逆数です。 |

## H

|  |  |
| --- | --- |
| <b><span id="histogram"></span>ヒストグラム（画像）</b> | 画像のコンテキストでは、ヒストグラムは指定された範囲（多くの場合[0, 1]）の値の母集団を表します。   この母集団は縦のバーを使用して視覚化されます。この場合、画像に含まれる値が大きいほど、その値のバーは高くなります。 棒は、低い値（暗）から高い値（明）まで水平方向に分布します。   通常、カラー画像のヒストグラムは、各チャンネル（通常はR、G、B）のヒストグラムと重なります。 |

## I

|  |  |
| --- | --- |
| <b><span id="inheritance"></span>継承</b> | Substanceグラフのコンテキストでは、上位ノードまたは親グラフからパラメータ値を取得するノードのプロパティを表します。   継承されたパラメーターには、[解像度](#resolution) （[出力サイズ](#output-size)）、[ビット深度](#bit-depth) （[出力形式](#output-format)）および[タイル](#tiling)モードが含まれます。   継承の詳細については、[専用ページ](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md)をご覧ください。 |
| <b><span id="instance-node"></span>インスタンスノード</b> | インスタンスノードはグラフAを別のグラフBに表す。その場合、グラフAはグラフBの[サブグラフ](#subgraph)と呼ばれることがあります。グラフAの変更は、グラフAを表すすべてのインスタンスノードに反映されます。   インスタンスノードは、グラフBのコンテキストでグラフAの入力パラメータに対して独自の値のセットを適用します。その意味で、グラフBは複数のインスタンスノードをホストすることができます。このインスタンスノードは、すべてのグラフAを参照しますが、グラフAへの入力として、それぞれ異なる値またはテクスチャを渡します。   [atomic nodes](#atomic-node)以外のDesigner Library内のノードはすべてインスタンスノードです。 |
| <b><span id="invalidation"></span>無効化</b> | ノードの結果が古いことを宣言するプロセス。   パラメーターを調整すると、このパラメーターをホストするノードと下流のすべてのノードが無効になるため、[評価](#evaluation)して[レンダリング](#rendering)する必要があります。 |

## M

|  |  |
| --- | --- |
| <b><span id="material"></span>マテリアル</b> | サーフェスと土量を含む、空間内の物質のプロパティと動作のコレクション。 3D空間での図形の外観は、そのマテリアルによって定義されます。   マテリアルは様々な方法で定義することができます。また、すべての定義で、屈折、異方性、光沢などのすべてのプロパティがサポートされているわけではありません。 [シェーダ](#shader)は、マテリアル定義の特定の実装です。   <b>重要：</b> 「マテリアル」という用語は、*包括的な用語*&#x200B;で、次のものを含むさまざまな用語を指して使用されます。<ul data-preserve-html="true"> <li data-preserve-html="true">サーフェスまたはボリュームの外観の計算に使用される[シェーダ](#shader)。</li> <li data-preserve-html="true">シェーダに提供された[テクスチャ](#texture)のセット；</li> <li data-preserve-html="true">マテリアルID。3Dプリミティブのアトリビュートで、異なるマテリアルを使用するパーツを区別するために使用されます。</li> </ul> |
| <b><span id="mesh"></span>メッシュ</b> | 三角形などの多角形を形成するためにエッジで接続された[頂点](#vertex)で構成される3Dオブジェクト。多角形は次にサーフェスに組み立てられます。 これらのサーフェスは、開いていても閉じていても構いません。   これらのサーフェスの外観は、サーフェスに割り当てられた[マテリアル](#material)によって定義されます。 メッシュの詳細レベルは、[ポリカウント](#polycount)にも大きく依存しています。 |
| <b><span id="metadata"></span>メタデータ</b> | ファイル自体、その環境、またはファイルのデータに関連する情報を提供するデータ。   一般的なメタデータには、ファイルの作成者、作成日と修正日、著作権とカバーアートが含まれます。   Designerでは、[パッケージ](#package)の内容にメタデータを含めることもできます。 たとえば、ファブリック・マテリアルを生成するSubstance・グラフには、ファブリックの物理プロパティのメタデータを含めることができます。 |
| <b><span id="mipmap"></span>Mipmap</b> | テクスチャの小さいバージョンで、多くの場合、自動的に計算されます。   テクスチャは、それ自体の小さいバージョンのピラミッドを持つことができます。ピラミッドは実行時に交換できるため、最適な品質とパフォーマンスを得るために最も適切なサイズが使用されます。   例えば、高周波ディテールを小さいサイズで表示したテクスチャは、*モアレ*&#x200B;のアーティファクトを生じる可能性があります。 さらに、大きなテクスチャには、より多くの[テクスチャサンプル](#texture-sampling)が含まれている可能性があります。   &#39;mipmap&#39;という用語は、MIPマッピング技術に由来します。MIPはラテン語の&#39;*multum in parvo*&#39; （「小さな場所に多くのものが存在する」という意味）を表します。 |

## N

|  |  |
| --- | --- |
